# PROTOCOL — план развития до уровня «лучше профессиональных СДО/LMS/LXP»

Дата: июль 2026. Основано на разборе современных LMS/LXP (360Learning, Disprz, iSpring, 1С:Электронный журнал колледжа, Open edX/RaccoonGang) и специфики СПО РФ.

## Что у нас уже есть
Курсы/уроки/блоки, сдача работ и проверка, оценки → XP/уровни/ранги, внутренняя валюта (монеты, по ролям), доска заданий, уведомления, группы и кураторы, роли (студент/препод/админ/супер-админ), тренажёры, портал как точка входа, доступность, i18n (RU/EN), админ-панель, полный аудит и экспорт в Excel.

## Чего не хватает против профи-платформ (и что делаем лучше)

### Milestone 1 — Учебное ядро колледжа (критично для СПО)
1. **Тесты/квизы с авто-проверкой** — банк вопросов (один/несколько верных, ввод, сопоставление), таймер, попытки, авто-оценка → тот же поток оценок/XP/монет. Чего нет у многих — авто-начисление геймификации за тест.
2. **Электронный журнал (grade book)** — сетка «группа × темы/уроки»: оценки, средний балл, экспорт в Excel. Ожидаемо для любого колледжа РФ.
3. **Посещаемость** — отметка присутствия за занятие, процент посещаемости в журнале и профиле.

### Milestone 2 — Организация и вовлечение
4. **Расписание/календарь + дедлайны** — таймтейбл занятий, сроки заданий, события; напоминания через запланированные уведомления.
5. **Сертификаты о прохождении** — авто-генерация именного сертификата (печатный/PDF) при завершении курса.
6. **Лидерборд + достижения/бейджи** — рейтинг по группе/заведению, ачивки («10 уроков», «SSS», «100 монет»), витрина достижений.
7. **Магазин за монеты** — трата валюты на рамки аватара/косметику (замыкает экономику монет).

### Milestone 3 — LXP/AI и коммуникации
8. **Глобальный поиск** — по курсам, урокам, людям (для админа).
9. **Обсуждения/вопросы** — комментарии к уроку, Q&A преподавателю.
10. **Аналитика** — дашборды прогресса, «студенты в зоне риска», воронка завершения.
11. **AI-помощник** — рекомендации курсов, подсказки по уроку, авто-конспект (при наличии API).
12. **Личные сообщения** — студент ↔ преподаватель/куратор.

## Принципы реализации
- Всё через существующую архитектуру: коллекции + миграции PocketBase, серверные хуки (server-authoritative для оценок/XP/монет), фич-флаги (`shared/config/features.ts`) для модульного включения.
- Единый тёмный стиль NEON GRID, адаптив, i18n RU/EN с паритетом ключей.
- После каждого этапа — проверка: `tsc`, паритет локалей, `node --check` хуков.

## Порядок
Идём по Milestone 1 → 2 → 3, фича за фичей, каждая — самодостаточный, проверяемый кусок. Начинаем с электронного журнала (низкий риск, без ломки схемы) и далее тесты/посещаемость.

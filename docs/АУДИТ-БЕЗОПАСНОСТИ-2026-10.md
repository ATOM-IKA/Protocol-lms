`protocol-lms.ru` и API `api.protocol-lms.ru` (только чтение), зависимости, история git.
Статусы: **Исправлено** — сделано в коде; **Сервер** — нужно действие на сервере (команды ниже);
**План** — осознанно отложено, с причиной.

## Критичные

1. **Исправлено — вход не работал.** Три ошибки в слое авторизации: (а) SDK вызывался с неверной сигнатурой
   (`authentication({storage})` вместо `authentication('json', {storage})`), хранилище сессии игнорировалось;
   (б) вызывалась REST-команда `login`, которая не сохраняет токен в клиенте — после «успешного» входа
   запросы шли без токена и получали `401`; (в) для студента запрос `/users/me` с полями, которых нет в правах,
   Directus не отклоняет, а молча отдаёт пустой профиль. Сессия также не переживала перезагрузку и могла
   оставаться «зомби» (интерфейс «залогинен», токен недействителен).
2. **Исправлено — в сборку был вшит адрес `127.0.0.1:8055`.** Добавлен `.env.production` с
   `VITE_DIRECTUS_URL=https://api.protocol-lms.ru`. Любая боевая сборка теперь смотрит на правильный API.
3. **Сервер — порт Directus 8055 открыт из интернета** (`0.0.0.0:8055`, `ufw` отключён): сервис доступен по
   обычному HTTP в обход nginx, HTTPS и лимитов. Исправление: `"127.0.0.1:8055:8055"` в `docker-compose.yml`
   (`deploy/nginx-directus-hardening.conf`, п. 3). Docker обходит `ufw`, поэтому дело именно в привязке порта.
4. **Сервер — вход без ограничения попыток.** 6 неверных паролей подряд — ни одного `429`. Нужен `limit_req`
   на `/auth/login` (п. 2.1 конфига) и `RATE_LIMITER_*` в Directus.
5. **Сервер — на сайте нет заголовков защиты** (HSTS, CSP, `X-Frame-Options`, `nosniff`, `Referrer-Policy`).
   Заголовки есть в репозитории, но не на сервере. Готовый набор — в конфиге (п. 1). Конфиг репозитория для
   PocketBase (`connect-src 'self'`) на Directus не подходит — заблокирует запросы к API.
6. **Сервер — панель Directus `/admin` открыта всем.** Ограничить по IP (п. 2.2); пароль технического админа
   `admin@mysite.ru` сменить, включить 2FA.
7. **Сервер — токен администратора был передан в чат.** Создать новый, старый удалить.

## Средние

8. **Исправлено — `react-router` 7.12–7.18 (high, CSRF в RSC-режиме).** В SPA режим не используется, но
   обновлено до исправленной версии.
9. **Исправлено — серверные поля.** `xp`, `level`, `rank`, `coins`, `progress_percent`, оценки, `score` не может
   писать ни одна роль (тест `directus/access.test.mjs` это гарантирует).
10. **Исправлено — подмена владельца.** Студент мог записать на курс другого и сдать работу «от чужого имени»;
    админ колледжа — создать пользователя/группу в чужом колледже. Владельца теперь ставит сервер.
11. **Исправлено — экран входа пускал в портал до проверки роли.** Студент на вкладке «Препод.» попадал в
    портал, а сообщение об ошибке не показывалось. Теперь роль и колледж проверяются до входа.
12. **План — токены сессии в `localStorage`.** При XSS их можно украсть. Смягчение: строгий CSP (п. 5).
    Правильное решение — httpOnly-cookie сессия (сайт и API на одном домене `*.protocol-lms.ru`, подходит);
    требует правок nginx/Directus и фронта, отдельным шагом.
13. **План — тренажёр кода (`new Function`, `/app/playground`).** Исполняет код пользователя на странице, поэтому
    CSP приходится держать с `'unsafe-eval'`. Решение — вынести тренажёр в изолированную песочницу
    (iframe с другого origin / worker), после чего убрать `'unsafe-eval'`.
14. **Сервер — загрузки `svg`/`html`.** Они нужны для учебных работ, но активное содержимое не должно
    исполняться: `Content-Security-Policy: sandbox` для `/assets/` (п. 2.3) и `FILES_MIME_TYPE_ALLOW_LIST`.
15. **План — Directus 10.13.4 устарел** (актуальна 11/12): обновление отдельным шагом, права при этом
    преобразуются в политики автоматически.
16. **Известные дыры, которые закроет серверное расширение (фаза 2).** Декларативными правами нельзя проверить
    владение при **создании** вложенных записей: преподаватель может создать раздел/урок/вопрос/посещаемость в
    чужом курсе; студент — записаться на неопубликованный курс или курс другого колледжа; прикрепить файл к
    чужой сдаче. **До установки расширения реальных пользователей на боевой базе быть не должно.**

## Низкие

17. Пароль нового пользователя в форме админа показан открытым текстом (удобно для выдачи, но виден с экрана).
18. Публичны `GraphQL` (с интроспекцией) и `/server/specs/oas`: `GRAPHQL_INTROSPECTION: "false"`.
19. На главной статистика читается из `site_stats`, а не из закрытых данных — исправлено (иначе гость
    получал `403`); пересчёт — `directus/refresh-stats.mjs`, позже расширение.

## Проверено и в порядке

- CORS: чужой origin разрешения не получает; сайт — получает.
- `http://` → `301` на `https://`; sourcemap'ов в боевой сборке нет.
- Секретов нет ни в отслеживаемых файлах, ни в истории; `.env*` игнорируются, `.env.production` — только публичный URL.
- XSS: `dangerouslySetInnerHTML`, `innerHTML`, `eval` в коде нет (кроме тренажёра, п. 13).
- Неверный пароль и несуществующий логин дают одинаковое сообщение (нельзя перебирать логины).
- Выход очищает сессию; подделанный токен сбрасывается; `/app/*` недоступен гостю, `/app/admin` — студенту.
- Обход пароля для разработки (`VITE_DEV_AUTH_BYPASS`) в боевой сборке отключён принудительно.
- База MariaDB наружу не опубликована (порт 3306 только внутри Docker-сети).
- Студент не видит email и студенческие номера одноклассников и правильные ответы тестов.

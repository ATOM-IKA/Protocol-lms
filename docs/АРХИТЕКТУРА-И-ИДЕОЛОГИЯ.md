# PROTOCOL — архитектура и идеология

Как система спроектирована и почему. Документ фиксирует принципы, роли, безопасность,
модульность и доступность — чтобы платформу можно было пересобирать под любого заказчика
и подтверждать соответствие требованиям (152-ФЗ, ФЗ-273, ПП №1678, ФГОС СПО).

---

## 1. Идеология: единая точка входа, разные зоны ответственности

- **Публичная зона (портал)** — лендинг, «Возможности», политика конфиденциальности. Маркетинг и навигация, без учебных данных.
- **Личный кабинет (профиль)** — ID-карта, ранг, средний балл. Витрина, не хранит лишнего.
- **Учебная зона (СДО/LMS)** — курсы, уроки, сдачи, оценки, прогресс, тренажёры.
- **Админ-зона** — управление пользователями, колледжами, курсами, аудит.

Одна платформа, но зоны разграничены ролями и правилами доступа. Термин «СДО» — для колледжа/госзадания (ссылки на ПП №1678, ФЗ-152), «LMS» — для корпоративного контекста; функционал один.

## 2. Компоненты (как реализовано)

| Роль из «эталонной» архитектуры | В PROTOCOL |
|---|---|
| Frontend-портал | React 19 + Vite + TS (`src/`), отдаётся nginx |
| IAM / SSO (учётки, токены, роли) | **PocketBase auth** — пароль + токен в `authStore`, роли в поле `role` |
| API Gateway (проверка токена, лимиты, логи) | **nginx** (проксирование, лимиты) + правила доступа PocketBase |
| СДО/LMS ядро | коллекции courses/sections/lessons/enrollments/submissions + серверные хуки |
| БД (ПДн, прогресс) | SQLite PocketBase (`pb_data`) |
| Аудит | коллекция `audit_logs` + хуки |

Стек защищён: фронт и API за одним nginx на одном домене по HTTPS (нет CORS и mixed-content).

## 3. Ролевая модель

- **student** — учёба: курсы своего колледжа, сдачи, прогресс, ранг по часам.
- **teacher** — свои курсы, открытие уроков, проверка и оценки; ранг по числу продвинутых студентов.
- **admin** — админ-панель в рамках **своего колледжа**.
- **superadmin** — вся система, все колледжи; ранг SSS+.
- *(план)* **parent** — кабинет родителя несовершеннолетнего (для СПО); **methodist** — работа с учебными планами.

Права разграничены на сервере (правила коллекций), а не только в интерфейсе.

## 4. Данные и минимизация (152-ФЗ)

- Храним минимум: student_id, ФИО, колледж, роль, учебная активность (прогресс, сдачи, оценки, XP). Спец-категории ПДн не собираются.
- Опыт, уровень, ранг и роль изменяются **только сервером** (хук `guardUserFields`) — клиент не подделает.
- Оценки ставит только преподаватель курса (серверный гвард); прохождение = оценка 3–5.
- Согласие на обработку ПДн — на входе; политика — на `/privacy`.

## 5. Безопасность (слои)

1. **Транспорт** — HTTPS/TLS везде, редирект с HTTP, HSTS.
2. **Заголовки** — CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy (`deploy/nginx-protocol-lms.conf`).
3. **Аутентификация/авторизация** — токены PocketBase, роли, разграничение по колледжам.
4. **Валидация загрузок** — тип/размер/количество файлов (клиент + серверные лимиты).
5. **Аудит** — логирование входов и изменений (`audit_logs`).
6. **Бэкапы** — регулярное копирование `pb_data` (см. `SECURITY.md`).

Подробности и чек-лист — в `SECURITY.md`.

## 6. Модульность (пересборка под заказчика)

Функциональные модули включаются/выключаются через единый конфиг **`src/shared/config/features.ts`**.
Отредактировав флаги и пересобрав фронт, систему можно «пересобрать» под нужды компании:

- `trainers` — библиотека тренажёров;
- `gamification` — опыт, уровни, ранги, аватары рангов;
- `averageGrade` — средний балл в профиле и на курсе;
- `institutions` — мультиколледжность (выбор заведения на входе);
- `accessibilityMenu` — меню спец-возможностей.

Так одна кодовая база обслуживает и «полную» СДО колледжа, и облегчённую корпоративную LMS.

## 7. Доступность (инклюзивность)

Отдельное **меню спец-возможностей** (иконка «глаз» в шапке): высокий контраст, крупный шрифт,
уменьшение анимаций, ч/б режим для дальтоников. Выбор сохраняется и применяется на всех страницах.
Плюс базовая доступность: семантика, alt-тексты, управление с клавиатуры, контраст ≥ 4.5:1.

## 8. Соответствие и аудит (для колледжа)

- **Действия пользователей** — логируются ключевые события (вход, изменение оценок, удаление данных).
- **Соответствие** — структура курса по РП/ФГОС, фиксация хода обучения.
- **Безопасность** — ревизия прав, паролей, неиспользуемых учёток.
- **Эффективность** — метрики в админ-обзоре (пользователи, курсы, записи, сдачи).

## 9. Развёртывание

- VPS + домен, nginx (статика + прокси PocketBase на 127.0.0.1), Let's Encrypt.
- Инструкции: `deploy/DEPLOY-HTTPS-BEGET.md`, шпаргалка команд: `deploy/ШПАРГАЛКА.md`.
- Отказоустойчивость — бэкапы `pb_data`, автопродление сертификата.

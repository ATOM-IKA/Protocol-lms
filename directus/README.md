# Directus: модель данных и права PROTOCOL LMS

Скрипты строят базу «с нуля» и проверяют права реальными запросами под каждой ролью.
Целевая версия: **Directus 10.13** (на 11 переезжаем отдельным шагом — права тогда сами станут политиками).

| Файл          | Что делает                                                                 |
| ------------- | -------------------------------------------------------------------------- |
| `model.mjs`   | Коллекции, поля, связи, четыре роли. Правится здесь — не в панели Directus |
| `access.mjs`  | Права каждой роли (кто что читает/пишет)                                   |
| `apply.mjs`   | Применяет модель к серверу. По умолчанию только показывает план            |
| `verify.mjs`  | Тест прав: пытается сделать запрещённое и убеждается, что оно запрещено    |
| `indexes.sql` | Составные уникальные ключи (генерируется `apply.mjs`)                      |

## Роли

`student` · `teacher` · `admin` (колледжа) · `superadmin`. У пользователя ровно одна роль.
Повысить студента до преподавателя может админ колледжа (только в своём колледже), до админа — только супер-админ.
Себе роль менять нельзя никому. Технический администратор Directus (`Administrator`) остаётся отдельно и нужен
только для настройки сервера.

## Запуск

Токен администратора Directus — в `.env.audit` (в git не попадает):

```
DIRECTUS_URL=https://api.protocol-lms.ru
DIRECTUS_STATIC_TOKEN=...
```

```bash
node directus/apply.mjs                       # 1. план, ничего не пишет
node directus/apply.mjs --reset --apply       # 2. применить (--reset пересоздаёт старую схему; откажется, если там есть данные)
node directus/apply.mjs --apply --seed-demo   # (по желанию) тестовые аккаунты по одному на роль
node directus/verify.mjs                      # 3. проверка прав (нужны демо-аккаунты)
```

Составные уникальные ключи Directus API не создаёт — выполните один раз на базе:

```bash
docker exec -i directus-project-database-1 sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"' < directus/indexes.sql
```

(если переменные в контейнере названы иначе — подставьте имя базы и пароль вручную).

## Боевой запуск — порядок

1. Резервная копия БД: `/opt/backup-directus-db.sh` (и копия `directus/` на сервере).
2. `node directus/apply.mjs --reset` — прочитать план.
3. `node directus/apply.mjs --reset --apply`, затем `indexes.sql`.
4. `--seed-demo` + `verify.mjs` → все проверки зелёные → **удалить демо-аккаунты**.
5. Завести реальных пользователей; сменить пароль/почту технического админа и включить 2FA.

Скрипт идемпотентен: после сбоя можно запустить повторно. Откат: восстановить БД из резервной копии шага 1.

## Что важно знать про Directus 10

- На роль + таблицу + действие действует **одна** запись прав. Скрипт отказывается собирать дубли.
- API **склеивает** дубли в списке прав без `id`, поэтому `apply.mjs` чистит права по числовым id.
- Владельца записи (`student`, `author`, `owner`, `reporter`, `institution` админа) клиент **не присылает**:
  его подставляет сервер (preset). Попытка прислать — `403`. Фронт должен эти поля не отправлять.
- Серверные поля (`xp`, `level`, `rank`, `coins`, `progress_percent`, `score`, `passed`, `xp_earned`, `graded_at`)
  не входят ни в одну роль на запись — их будет менять серверное расширение (фаза 2).
- Правильные ответы тестов (`quiz_questions.correct`) студенту недоступны.
- Студент видит одноклассников без email и студенческого номера; номер — это логин.

## Что закрывает следующая фаза (серверное расширение)

Декларативными правами нельзя проверить «владение» при **создании** вложенных записей (раздел/урок/тест в чужом
курсе, запись на чужой колледж). Это, а также расчёт XP, оценок, монет, тестов, уведомлений, рейтинга и журнала
аудита делает расширение Directus (`directus/extension`, фаза 2). До его установки на боевой базе реальных
пользователей быть не должно.

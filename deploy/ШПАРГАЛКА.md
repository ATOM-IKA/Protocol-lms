# PROTOCOL LMS — шпаргалка по деплою

Все команды для сборки и развёртывания. Значения уже подставлены:

- Сервер: `root@159.194.237.33`  ·  Домен: `https://protocol-lms.ru`
- Проект на ПК: `E:\protocol-lms`
- Сайт на сервере: `/var/www/protocol-lms/dist`
- PocketBase на сервере: `/root` (сервис `pocketbase`, порт `127.0.0.1:8090` за nginx)

Метки: **[ПК]** — PowerShell на твоём компьютере, **[СЕРВЕР]** — терминал сервера (после `ssh`).

---

## 0. Зайти на сервер по SSH  [ПК]

```
ssh root@159.194.237.33
```
Ввести пароль root (не отображается). Выйти обратно — `exit`.

---

## 1. Собрать и выложить сайт (обычный деплой)  [ПК]

Выполнять по очереди в PowerShell. Каждая команда с `ssh`/`scp` спросит пароль.

```
cd E:\protocol-lms
```
```
npm run build
```
```
ssh root@159.194.237.33 "rm -rf /var/www/protocol-lms/dist"
```
```
scp -r dist root@159.194.237.33:/var/www/protocol-lms/dist
```

Потом открыть **https://protocol-lms.ru** и обновить страницу **Ctrl+F5**.

> `rm -rf` перед `scp` важен: иначе новая папка ляжет внутрь старой (`dist/dist`) и сайт не обновится.

## 2. Первичная установка зависимостей  [ПК]

Нужно один раз (или после обновления package.json):

```
cd E:\protocol-lms
```
```
npm install
```

Запуск локально для разработки (открывается на http://localhost:5173):

```
npm run dev
```

---

## 3. Обновить бэкенд PocketBase (миграции и хуки)  [ПК]

Когда менялись файлы в `pocketbase\pb_migrations` или `pocketbase\pb_hooks`:

```
cd E:\protocol-lms
```
```
ssh root@159.194.237.33 "systemctl stop pocketbase && rm -rf /root/pb_migrations /root/pb_hooks"
```
```
scp -r pocketbase\pb_migrations root@159.194.237.33:/root/pb_migrations
```
```
scp -r pocketbase\pb_hooks root@159.194.237.33:/root/pb_hooks
```
```
ssh root@159.194.237.33 "systemctl start pocketbase && systemctl status pocketbase --no-pager"
```

В статусе должно быть `active (running)` без строк про ошибку миграции.

---

## 4. Перенести базу данных с ПК на сервер  [ПК]

Если нужно залить локальную базу (колледжи, пользователи, курсы) заново.
Внимание: заменяет базу на сервере.

```
ssh root@159.194.237.33 "systemctl stop pocketbase && rm -rf /root/pb_data"
```
```
scp -r E:\pocketbase_pb\pb_data root@159.194.237.33:/root/pb_data
```
```
ssh root@159.194.237.33 "systemctl start pocketbase"
```

## 5. Управление PocketBase  [СЕРВЕР] или через ssh "..."

```
systemctl status pocketbase        # состояние
systemctl restart pocketbase       # перезапустить
systemctl stop pocketbase          # остановить
systemctl start pocketbase         # запустить
journalctl -u pocketbase -f        # смотреть логи в реальном времени (выход Ctrl+C)
```

Проверить, что API отвечает и данные на месте:
```
curl -s http://127.0.0.1:8090/api/collections/institutions/records ; echo
```

Админка PocketBase (в браузере): **https://protocol-lms.ru/_/**

---

## 6. Управление nginx  [СЕРВЕР]

```
nginx -t                           # проверить конфиг (syntax is ok)
systemctl reload nginx             # применить изменения конфига
systemctl restart nginx            # полный перезапуск
```
Конфиг сайта: `/etc/nginx/sites-available/protocol-lms.conf`

## 8. Быстрая диагностика, если сайт «не тот»

1. Открыть `https://protocol-lms.ru/api/collections/institutions/records` — должен быть JSON с колледжами. Нет → проблема с PocketBase/nginx.
2. На сайте нажать **F12 → Console**. Красный `Mixed Content` → старая сборка, повторить раздел 1. `Failed to fetch` → см. PocketBase (раздел 5).
3. Имя файла `index-….js` в консоли не сменилось после деплоя → на сервере лежит старая сборка (раздел 1, не забыть `rm -rf`).

## Частые ошибки

- `scp - r ...` не работает — флаг пишется слитно: **`-r`**, без пробела.
- Команда «прыгает» на две строки при вставке — набери её вручную или собери в одну строку.
- `path canonicalization failed` у scp — на сервере нет родительской папки: `ssh root@159.194.237.33 "mkdir -p /var/www/protocol-lms"`, потом повторить scp.

# PROTOCOL LMS — безопасность

Чек-лист по защите продакшена. Разделено на то, что уже сделано в коде, и то, что
нужно включить при развёртывании.

## Секреты: что и где хранится (актуально для Directus)

Правило: **в репозитории и в собранном сайте нет ни паролей, ни токенов, ни ключей.**

| Что | Где живёт | В git |
|---|---|---|
| Токен администратора Directus для скриптов, `DEMO_PASSWORD` | файл `.env.audit` на вашей машине/сервере | нет (`.env.*` в `.gitignore`) |
| Адрес API (`VITE_DIRECTUS_URL`) | `.env.production` | да — это публичный адрес, не секрет |
| `KEY`, `SECRET`, пароль БД Directus | `docker-compose.yml` / `.env` на сервере | нет |
| Пароли пользователей | только в БД Directus, хешируются | нет |

Защита от случайных утечек:
- `npm run hooks` — один раз после клонирования: включает проверку перед каждым коммитом (`.githooks/pre-commit`).
- `npm run check:secrets` — проверка всех файлов репозитория; `npm run build` автоматически проверяет и готовый сайт (`postbuild`).
- Сканер ищет токены, ключи, `Bearer`-заголовки, пароли и логины в адресах; заведомо ненастоящую заглушку в тесте
  помечают комментарием `secret-scan:ignore`.
- Если секрет всё же попал в git — считайте его скомпрометированным: **сначала отзовите/смените его**, и только потом
  чистите историю (удаление из истории не вернёт то, что уже скачали).
- Тестовые аккаунты (`student-0001` …) — только для проверки. Перед запуском для реальных пользователей их нужно
  удалить или сменить пароли; простые пароли на открытом сервере подбираются за секунды.

## Уже реализовано в коде

- **Серверный авторитет по опыту.** XP, уровень, ранг и роль пересчитываются только
  хуком PocketBase (`pb_hooks/main.pb.js`); попытки клиента их изменить откатываются
  (`guardUserFields`).
- **Оценки — только сервер.** Статус и оценка сдачи проставляются серверным хуком;
  студент не может выставить оценку себе.
- **Изоляция по колледжам и ролям.** Правила доступа коллекций (`SCHEMA.md`): студент
  видит только опубликованные курсы своего колледжа и свои данные; преподаватель —
  свои курсы и работы своих студентов.
- **Валидация загрузок (клиент).** `src/shared/lib/upload.ts`: до 3 файлов, каждый до
  10 МБ, только разрешённые типы (документы, изображения, архивы, код).
- **Согласие на обработку ПДн (152-ФЗ).** Чекбокс на входе + страница `/privacy`.
- **Без внешних CDN в проде.** Шрифты и библиотеки собираются в бандл — CSP может быть
  строгим (`default-src 'self'`).
- **XSS.** Контент уроков и файлы выводятся как текст (без `dangerouslySetInnerHTML`);
  React экранирует по умолчанию.

## Включить при развёртывании

### 1. HTTPS + security-заголовки
- Разверните по `deploy/DEPLOY-HTTPS-BEGET.md` (Let's Encrypt).
- Заголовки уже в `deploy/nginx-protocol-lms.conf` (CSP, HSTS, X-Frame-Options,
  X-Content-Type-Options, Referrer-Policy, Permissions-Policy).
- HSTS включайте только после того, как HTTPS точно работает.

### 2. Валидация загрузок на сервере (PocketBase)
В админке → коллекция **submissions** → поле **files**:
- **Max file size**: `10 MB`.
- **Max select**: `3`.
- **Mime types**: перечислите разрешённые (например `application/pdf`, `image/png`,
  `image/jpeg`, `application/zip`, `text/plain`, документы Office). Пустой список = любые.

### 3. Rate limiting (защита от перебора паролей и флуда)
PocketBase (v0.23+) → **Settings → Application → Rate limiting**: включите и задайте
правила, например:
- `*` → 300 запросов / 60 c на IP;
- `/api/collections/users/auth-with-password` → 5 запросов / 60 c (защита логина).

### 4. Политика паролей
- При создании пользователей задавайте пароль **не короче 10 символов**.
- В **Settings → Auth** у коллекции users можно задать минимальную длину пароля.
- Отключите открытую регистрацию (у нас пользователей создаёт админ) — правило
  `createRule` коллекции users уже `@request.auth.role = "admin"`.

### 5. Доступ к админке PocketBase
- Придумайте суперпользователю длинный уникальный пароль.
- По возможности закройте `/_/` по IP (в nginx `location /_/ { allow <ваш IP>; deny all; ... }`).

### 6. Резервные копии
- Регулярно копируйте папку `pb_data/` (в ней вся БД и файлы). PocketBase умеет бэкапы
  в **Settings → Backups** (в т.ч. по расписанию и в S3).

### 7. Секреты и окружение
- Не коммитьте `.env` с реальными адресами/ключами.
- На VPS ограничьте права на файлы `pb_data` (владелец — пользователь сервиса).

## Быстрая проверка после деплоя
- Замок зелёный, `http://` редиректит на `https://`.
- Заголовки видны: `curl -I https://ваш-домен` → есть `Strict-Transport-Security`,
  `Content-Security-Policy`, `X-Frame-Options`.
- Студент не может изменить свой XP (`PATCH /api/collections/users/records/<id>` с
  `{"xp":999999}` — значение не меняется).
- Студент другого колледжа не видит чужие курсы.
- Загрузка `.exe` или файла > 10 МБ отклоняется.

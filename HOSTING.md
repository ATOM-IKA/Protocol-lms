# PROTOCOL LMS — сборка и деплой на хостинг

## 1. Сборка (у себя, один раз)

Нужен Node.js 20+. В папке проекта:

```powershell
npm install       # если ещё не делали / менялся package.json
npm run build
```

Появится папка **`dist/`** — это и есть готовый сайт (статические файлы).

Проверить локально перед заливкой:

```powershell
npm run preview   # откроет собранную версию
```

## 2. Что заливать

Заливайте **содержимое папки `dist/`** (не саму папку) в корень вашего хостинга.

Демо работает полностью на клиенте: сессия и прогресс хранятся в браузере
(`localStorage`), бэкенд для проверки не нужен.

## 3. Важно: SPA-маршрутизация

Приложение использует клиентские маршруты (`/app`, `/app/courses/:id` и т.д.).
Хостинг должен **отдавать `index.html` на любой путь**, иначе при обновлении
страницы `/app/...` будет 404. Нужные конфиги уже включены:

- **Netlify** — файл `public/_redirects` (попадёт в `dist/`), ничего делать не нужно.
- **Apache / cPanel / хостинги с .htaccess** — `public/.htaccess` (попадёт в `dist/`).
- **Vercel** — `vercel.json` в корне проекта.
- **Nginx** — добавьте в конфиг сайта:

  ```nginx
  location / {
    try_files $uri /index.html;
  }
  ```

- **GitHub Pages** — SPA-фолбэк работает иначе; проще Netlify/Vercel.

## 4. Если сайт в подпапке (например, site.ru/lms/)

Откройте `vite.config.ts`, добавьте `base`:

```ts
export default defineConfig({
  base: '/lms/',
  // ...
})
```

и пересоберите (`npm run build`).

## 5. Переменные окружения

`.env` не обязателен для демо. Когда подключим реальный PocketBase, туда
добавляется `VITE_POCKETBASE_URL=...` **до** `npm run build` (значение
«запекается» в сборку).

## Примечание

Собрать `dist/` в среде Cowork нельзя (заблокирован доступ к npm-реестру),
поэтому сборка выполняется у вас локально по шагам выше. Код к сборке готов:
проверены синтаксис, разрешение импортов и цветовые токены.

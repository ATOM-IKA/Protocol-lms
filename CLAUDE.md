# Правила работы (экономия токенов + безопасность)
- НИКОГДА не читай и не листай node_modules, dist, build, .git, логи, *.lock, vendor.
- Прежде чем менять код или запускать команды сборки/тестов — покажи ПЛАН и жди моего «ок». Не применяй правки молча.
- Отвечай кратко. Код — без поясняющих простыней, если я не просил объяснений.
- Не запускай сетевые команды, деплой, git push без явного запроса.
- Для поиска по проекту используй grep/поиск, а не чтение файлов целиком.
- Если задача неясна — задай 1 вопрос, не угадывай и не читай полпроекта.

# Принципы кодирования (источник: multica-ai/andrej-karpathy-skills, MIT)
Компромисс: осторожность важнее скорости. Для тривиальных задач используй здравый смысл.

1. **Think Before Coding.** Не предполагай, не скрывай непонимание, называй компромиссы. Явно указывай допущения; если несколько трактовок — покажи их, не выбирай молча; если есть проще решение — скажи; если неясно — остановись и спроси.
2. **Simplicity First.** Минимум кода, решающий задачу. Без функций сверх запроса, абстракций под один случай, лишней настраиваемости и обработки невозможных ошибок. Если можно в 50 строк — не пиши 200.
3. **Surgical Changes.** Меняй только то, что нужно. Не «улучшай» соседний код, комментарии и форматирование; не рефакторь нерабочее; следуй существующему стилю. Мёртвый код, который не твой, — упомяни, но не удаляй. Удаляй только импорты и функции, ставшие лишними из-за твоих правок.
4. **Goal-Driven Execution.** Превращай задачу в проверяемую цель («баг → тест, воспроизводящий его, затем сделать тест зелёным»). Для многошагового плана: `1. [шаг] → проверка: [что проверяем]`.
